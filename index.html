I've spent six years doing that across open-source developer ecosystems — in positioning, launches, developer experience, education, and growth. More recently, I've been applying the same method to AI infrastructure, observability, evals, and agent tooling.

Product / Competitive Analysis

The trace-to-eval loop is table stakes. Where it runs is the actual decision.

I wanted to know whether Langfuse and LangSmith meaningfully differ on the workflow every observability vendor now demos: bad production trace → dataset → eval → regression test.

I built the full loop in Langfuse and reconstructed the LangSmith path from its current docs. The interesting result was that the loop itself wasn't the differentiator. Deployment boundary and framework coupling were.

The piece is explicit about the asymmetry: one side is hands-on, the other researched. I don't call something a benchmark when it isn't one.

Developer Experience

Langfuse Docs: Friction Notes from a First Run

I kept a friction log while building against the Python SDK rather than trying to reconstruct the experience afterwards.

The interesting problems weren't missing APIs. They were mismatches between what the system was doing and what a new user could infer from the symptom in front of them.

A script exits successfully but no trace appears. Auto-instrumentation changes the path for linking a prompt to a generation. Legacy configuration names create ambiguity even when compatibility code prevents an error.

Each note ends with the smallest docs change I'd actually propose in a PR.

About

I ended up in product marketing from the wrong direction.

I started close to developers: helping teams get from an idea to a working integration, fixing onboarding gaps, owning docs, teaching SDKs, and watching launches fail in ways the launch metrics didn't explain.

Over time the recurring problem became obvious: technically correct products can still be badly understood. A feature can ship, documentation can exist, traffic can arrive — and adoption can remain near zero because the story is about the mechanism instead of the job.

That's the part I like working on.

My background is unusually mixed: developer ecosystems and GTM professionally, mathematics and computer science academically, and enough Python and Rust to inspect what I'm supposed to be marketing before I form an opinion about it.

Berlin / remote. Currently interested in AI infrastructure and developer products where the technical details actually change the GTM story.
